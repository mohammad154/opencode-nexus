# OpenCode Nexus V4.1 Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement and verify all 16 audit findings for OpenCode Nexus V4.1 hardening, ensuring strict fail-closed enforcement across state machine, providers, locks, worktrees, uninstaller, DAG scheduler, and reviewer identity.

**Architecture:** Enforce the invariant: *Agents propose facts, providers measure facts, state machine decides*. State transitions require verified evidence (authoritative git diffs, provider test executions, sealed artifacts, locked revisions).

**Tech Stack:** Node.js (ESM), `node:test`, `node:child_process`, `node:fs`, JSON Schema draft-07.

**Spec:** [`docs/superpowers/specs/2026-08-20-nexus-v4.1-hardening-design.md`](file:///home/danaee/opencode-nexus/docs/superpowers/specs/2026-08-20-nexus-v4.1-hardening-design.md)

## Global Constraints
- Node.js >= 20 ESM codebase with strict `shell: false` execution.
- Maintain existing valid transitions while making gates strictly fail-closed.
- Preserve backward compatibility with V4 run states and configurations.
- All 222+ existing tests and new regression tests must pass cleanly.
