# OpenCode Nexus V4.1 Hardening Design Specification

- **Date:** 2026-08-20
- **Version:** 4.1.0-spec
- **Status:** Approved for Implementation

---

## 1. Executive Summary & Core Principle

OpenCode Nexus V4 established a state-machine driven, evidence-based development workflow for multi-agent systems. The V4.1 Hardening release enforces the core architectural invariant:

> **Agents propose facts. Providers measure facts. State machine only accepts measured facts.**

This specification resolves all audit findings across 4 priority categories:
1. **P0 (Critical Reliability & Concurrency):** Verification fail-closed on zero checks, structured `BLOCKED` checkpoint to prevent gate bypass, atomic `O_EXCL` run-state locking, and uninstaller agent restoration.
2. **P1 (Engine Enforced Gates):** Authoritative git-diff scope locking, worktree isolation helper bugs & CLI, provider-measured TDD evidence, strict reviewer identity/anti-self-approval enforcement, and Task DAG correctness.
3. **P2 (Engine Accuracy & DX Polish):** Multi-language impact confidence fixes, risk ladder step filtering, `nexus run baseline` CLI entry point, and Graphify legacy path retirement.
4. **Cleanup:** Untracking generated runtime cache/impact artifacts, and synchronizing README and agent definitions with V4 architecture.

## 2. Detailed Technical Design by Subsystem

### 2.1 Verification Provider & Fail-Closed Enforcement

#### Problem
In `verification-provider.js`, `results.every(x => x.pass === true || x.status === "UNAVAILABLE")` evaluates to `true` on an empty array `[]` or when all checks are `UNAVAILABLE`. Node projects without scripts reach `COMPLETED` without any check ever running.

#### Solution
- Filter `results` to collect executed checks:
  ```js
  const executed = results.filter(
    (r) => r.status !== "UNAVAILABLE" && r.exit_code != null
  );
  if (executed.length === 0) {
    return {
      ok: false,
      code: "VERIFICATION_UNAVAILABLE",
      results,
      plan,
    };
  }
  ```
- Retain explicit exemptions only when persisted in state: `state.verification_policy.exempt === true` (e.g. for pure docs/formatting changes classified via `classify --apply`).

#### Risk-Based Verification Ladder
- `verificationLadder(risk)` produces required levels:
  - `LOW`: `["related_tests", "lint"]`
  - `MEDIUM`: `["related_tests", "lint", "typecheck"]`
  - `HIGH`: `["related_tests", "full_tests", "lint", "typecheck", "build"]`
  - `CRITICAL`: all levels above + full build & test requirement.
- In `discoverVerification(worktree, options)` and `verification-provider.js`:
  - When a risk level is provided in options/context, filter or mark steps accordingly, ensuring `HIGH` and `CRITICAL` changes execute the full test suite while `LOW` prioritizes targeted related tests and linting.

### 2.2 Structured `BLOCKED` Checkpoint & Atomic Concurrency

#### Problem 1: Gate Bypass via `BLOCKED`
`BLOCKED + resume_to` permitted arbitrary non-terminal states. A run blocked during `VERIFYING` could resume directly to `REVIEWING` without running provider verification gates.

#### Solution
- On transition to `BLOCKED`, the state machine persists:
  - `blocked_from`: state prior to blocking (e.g. `"VERIFYING"`)
  - `resume_state`: target resumption state (defaults to `from` or explicitly provided `ctx.resume_state`)
  - `block_code`: classification code (e.g. `"SCOPE_EXPANSION_REQUIRED"`)
  - `block_reason`: human-readable explanation
- Transitions from `BLOCKED`:
  - Only permit `to === state.resume_state || to === state.blocked_from` (or `FAILED`).
  - Resumption transitions execute all validation gates of the target state (e.g., verifying provider verification if resuming to `REVIEWING` or `FINAL_VERIFYING`).

#### Problem 2: Race Conditions in `writeRunState()`
`writeRunState()` in `scripts/lib/migrate-artifacts.js` read the existing file revision and later renamed a temp file without holding an advisory lock.

#### Solution
- Implement a shared lock utility in `scripts/lib/lock.js`:
  - Uses `fs.openSync(lockPath, "wx")` (`O_EXCL`).
  - Includes stale lock reaping (age > 10,000ms).
  - Exponential backoff with retry loop (up to 100 retries, 5ms delay).
- In `writeRunState(worktree, state)`:
  - Execute the entire read-revision, revision comparison, temp file write, and atomic rename within `withFileLock(target, ...)`.
  - Throw `Error("run state revision conflict...")` with `err.code = "REVISION_CONFLICT"` when revision mismatch occurs.

### 2.3 Canonical Agent Roster & Uninstall Safety

#### Problem
`install.sh` installs 8 canonical agents, but `uninstall.sh` only handled 6, omitting `diagnostician` and `integration-reviewer`. `uninstall.sh` then deleted the manifest and `*.nexus-original.*` backups, causing data loss for pre-existing user agent files.

#### Solution
- Create `scripts/lib/constants.js`:
  ```js
  export const CANONICAL_AGENTS = Object.freeze([
    "orchestrator",
    "implementer",
    "diagnostician",
    "unified-reviewer",
    "spec-reviewer",
    "code-reviewer",
    "integration-reviewer",
    "reconciler",
  ]);
  export const OPTIONAL_AGENTS = Object.freeze(["blast-analyzer"]);
  ```
- Update `uninstall.sh` to iterate through all 8 canonical agents and `blast-analyzer` for `bak_restore`.
- Update `install.sh`, `bin/nexus.js` (`doctor` command), and test suites (`test-install-only.sh`, `test-uninstall-lifecycle.sh`) to reference the complete canonical roster.

### 2.4 Authoritative Git-Diff Scope Gate, Worktrees & TDD Evidence

#### 1. Scope Lock Gate
- When transitioning to `VERIFYING`, the state machine/provider executes `git diff --name-only <base_commit>..<implementer_commit>` (or against HEAD).
- The authoritative list of changed files is compared against `state.allowed_files` (or `ctx.allowed_files`) via `assertScopeLock()`.
- If out-of-scope files were edited:
  - Transition fails or transitions to `BLOCKED` with `block_code: "SCOPE_EXPANSION_REQUIRED"`.

#### 2. Git Worktree Helper & CLI
- In `scripts/lib/worktree.js`:
  - Fix `createTaskWorktree`: pass `baseCommit || "HEAD"` to `git worktree add -b <branch> <dir> <baseCommit>`.
  - Trim stdout in all rev-parse checks: `wtHead.stdout.trim() !== baseCommit.trim()`.
- Add CLI commands to `bin/nexus.js` and `scripts/nexus-run.js`:
  - `nexus worktree create --task <id> [--branch <name>] [--base <sha>]`
  - `nexus worktree list`
  - `nexus worktree remove --task <id>`

#### 3. Provider-Sealed TDD Evidence
- Implement TDD verification provider method:
  - Executes test command at `base_commit` (verifying non-zero exit code = RED).
  - Executes test command at `implementer_commit` (verifying 0 exit code = GREEN).
  - Produces a sealed TDD evidence report artifact containing commit SHAs, exit codes, and output digests.
- State machine checks sealed TDD artifact when `tdd_required` is enabled on bug fixes.

### 2.5 Reviewer Identity & Task DAG Correctness

#### 1. Reviewer Identity Enforcement
- In `scripts/lib/state-machine.js`:
  - Enforce `unified.agent === "unified-reviewer"`.
  - Enforce `spec.agent === "spec-reviewer"` and `code.agent === "code-reviewer"` in dual review mode.
  - Enforce `integration.agent === "integration-reviewer"` in multi-task runs.
  - Enforce `reviewer.agent !== implementer.agent` across all review modes.
  - Enforce `spec.agent !== code.agent` in dual review mode.
- Update schemas (`schemas/handoff-spec-reviewer.schema.json`, `schemas/handoff-code-reviewer.schema.json`, `schemas/handoff-integration-reviewer.schema.json`, `schemas/handoff-unified-reviewer.schema.json`) with enum constraints on `agent`.

#### 2. Task DAG Robustness
- In `scripts/lib/task-dag.js`:
  - Reject duplicate task IDs during `buildTaskDag(tasks)` by throwing an error if `byId.has(t.id)`.
  - In `scheduleParallel(dag, { completed })`: validate and filter `completed` set against known DAG tasks (`dag.byId.has(id)`).
  - In `scripts/lib/impact/boundaries.js`: enhance `globsOverlap(a, b)` to evaluate wildcard prefix/suffix combinations correctly.

### 2.6 Impact Engine Confidence & CLI Polish

#### 1. Multi-Language Confidence
- In `scripts/lib/impact/analyze.js`:
  - Fix double counting: check `if (!adapterSupports(lang) && lang !== "unknown") unsupportedFiles += 1;` once per file.
  - Scope `parseErrors` in confidence calculation to changed files rather than the entire repo index stats.

#### 2. Baseline CLI
- Expose `nexus run baseline` / `nexus verify --baseline` in `bin/nexus.js` and `scripts/nexus-run.js` to create or compare verification baselines against `baseline.json`.

#### 3. Legacy Graphify Trust Retirement
- Deprecate inline untrusted graphify trust paths; enforce recomputed Impact Engine reports.
- Move any legacy V3 compatibility docs to `docs/compatibility-v3.md` and clean up `README.md`.

#### 4. Repository Cleanup
- Untrack `.opencode/cache/impact/*` and `.opencode/impact/latest.json` from git while preserving `.gitignore` entries.

## 3. Verification Plan & Test Strategy

Comprehensive test coverage will be added across all modified subsystems:
1. `tests/verification-provider.test.js`: Empty plan / zero-check failure, all-UNAVAILABLE failure, risk ladder selection.
2. `tests/state-machine-blocked.test.js`: Structured BLOCKED checkpoint enforcement, rejection of arbitrary resume destinations, gate execution upon resume.
3. `tests/run-state-lock.test.js`: Concurrent `writeRunState` race simulation verifying atomic rejection with `REVISION_CONFLICT`.
4. `tests/uninstall-lifecycle.test.js`: Verification of all 8 canonical agents and backup restoration.
5. `tests/scope-lock.test.js`: Authoritative git-diff scope validation during transitions.
6. `tests/worktree.test.js`: Base commit support and whitespace trimming in worktree reuse.
7. `tests/tdd-provider.test.js`: Provider-measured RED/GREEN execution and sealed artifact verification.
8. `tests/reviewer-identity.test.js`: Dual and unified reviewer identity and anti-self-approval validation.
9. `tests/task-dag.test.js`: Duplicate ID rejection, completed set bounds, glob overlap edge cases.
10. `tests/impact-confidence.test.js`: Unsupported language confidence single-counting and parse error scoping.
